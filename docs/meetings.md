# Конференции в Ferrofluid Voice

Откройте библиотеку кнопкой на виджете и выберите **Конференции**.

1. Нажмите **Новая запись** и выберите файл Zoom (M4A), WAV, MP3, FLAC, OGG, AAC или MP4.
2. При первом запуске нажмите **Установить движок**. Нужны Python 3.10+ (рекомендуется 3.11) и FFmpeg. Зависимости устанавливаются в отдельное окружение приложения; системные Python-пакеты не меняются.
3. Укажите количество участников, если оно известно, и нажмите **Найти голоса**. Автоопределение создаёт предварительные группы и может ошибаться на шуме и коротких фразах.
4. Прослушайте образцы через значок наушников и введите имена. Группы одного участника можно объединить. При необходимости добавьте участника вручную: образец возьмётся с текущей позиции плеера.
   Если голоса перепутаны, заполните **Подтверждённые образцы голосов**: начало и конец 7–120 секунд чистой речи каждого участника, в формате `03:14` или `00:03:14`. Можно добавить несколько образцов одного человека. Нажмите **Уточнить голоса**. Калибровка обновляет метки всей записи, сохраняя текст и таймкоды. При первом запуске загрузится отдельная модель (~27 МБ). Образцы разных участников не должны пересекаться.
5. Выберите язык и нажмите **Создать транскрипт**. Используется выбранная в настройках модель Whisper. Имена и изменения сохраняются перед обработкой.
6. Проверьте отмеченные реплики, поправьте текст и участника. Для разделения реплики выберите момент внутри неё на аудиодорожке и место в тексте, затем нажмите **Разделить**. После проверки нажмите **Проверить ✓**, чтобы снять отметку.
   При ручном выборе участника имя закрепляется: повторная калибровка его не изменит. Нажмите **Имя закреплено · снять**, чтобы снова разрешить автоматическое назначение. Если в старой реплике говорят разные люди или совпадение с образцом неуверенное, калибровка оставит её без имени для проверки. До калибровки сохраняется резервная копия `before-calibration-….json`.
7. Нажмите **Сохранить** после ручных изменений. Экспорт доступен в TXT, SRT и JSON: все форматы содержат имена, TXT/SRT — таймкоды. При переключении конференции и экспорте изменения также сохраняются.

Голоса — условные группы, а не автоматически установленные личности. Имена назначает пользователь. Одновременную речь и сомнительное сопоставление приложение отмечает для проверки; движок не разделяет смешанные голоса на отдельные аудиодорожки.

## Уточнение реплик

После создания транскрипта и подтверждения образцов нажмите **Уточнить реплики**, выбрав язык встречи. Приложение создаёт **отдельную уточнённую версию**, доступную в списке конференций. Исходная версия остаётся доступной. Повторный запуск использует локальный кэш; изменения текста или языка сбрасывают кэш выравнивания.

Точный режим использует локальный NVIDIA Nemotron-3-Diarization для границ говорящих и одновременной речи, CAM++ для сопоставления чистых интервалов с вашими образцами и WhisperX/wav2vec2 CTC для выравнивания **существующего текста** по аудио. Повторного распознавания текста нет. Слова сохраняются в исходном порядке; меняются их группировка и таймкоды. Закреплённые реплики сохраняются целиком. Если слово не получило надёжный таймкод либо в интервале слышны несколько голосов, соответствующий текст остаётся для проверки.

Первая установка выравнивания требует интернета, нескольких минут и свободного места на диске: отдельное окружение PyTorch и русская модель wav2vec2 (около 1.26 ГБ). После загрузки обработка русской записи полностью локальная. Для других языков модель загружается при первом использовании. Зависимости устанавливаются в `meetings/engine/alignment-runtime`, системные Python-пакеты не меняются. Рабочие модели и кэш находятся в каталоге данных приложения, аудио в сеть не отправляется.

Движок Windows NVIDIA собран из официального [NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp) commit `4c101bc7113f49101a3e11d2c994c519f41939f6`. В этой сборке включён CUDA backend для установленной RTX 5080; нужен совместимый CUDA runtime. Native exe и DLL находятся в `src-tauri/binaries/nemo` и копируются рядом с приложением в `binaries/nemo`. При отсутствии комплектного runtime можно использовать установленный экземпляр в `meetings/engine/nemo/current/bin`. Готовый релиз NeMo-Speech.cpp 0.1.0 с GitHub ещё не поддерживает новый checkpoint: подменять им этот runtime нельзя.

Для воспроизведения сборки на Windows:

```powershell
git clone https://github.com/NVIDIA/NeMo-Speech.cpp.git tools/nemo-speech
git -C tools/nemo-speech checkout 4c101bc7113f49101a3e11d2c994c519f41939f6
& tools/nemo-speech/scripts/windows/build.ps1 -Backend cuda -Profile asr -CudaArch 120 -Jobs 12
```

Модель NVIDIA закреплена на ревизии `f667ed73aee57d40cc39428eb768b4fd87a0a29e`, русская wav2vec2 — на `2329100508896c6d9b157019803ab5601e6f3406`. Перед использованием проверяются SHA-256 весов. Версии WhisperX/PyTorch/Transformers закреплены в worker. Для Community-1 проверка настроенного Hugging Face доступа вернула HTTP 403: этот вариант не использован, поскольку его условия доступа ещё не приняты.

## Локальные данные

Записи и метаданные хранятся в каталоге данных приложения `Ferrofluid Voice/meetings/meeting-…`. Исходник не изменяется: FFmpeg создаёт рабочую копию PCM16, 16 кГц, моно. Транскрипты конференций не добавляются в историю диктовки и не вставляются в активное окно.

Модели и изолированное Python-окружение находятся в `Ferrofluid Voice/meetings/engine`. Интернет нужен только для установки зависимостей и скачивания моделей. Распознавание и воспроизведение используют локальные файлы.

Поддерживаются переменные окружения:

- `FERROFLUID_MEETINGS_PYTHON`: путь к Python для первоначальной установки.
- `FERROFLUID_FFMPEG_BIN`: путь к FFmpeg, если он не находится в PATH.
- `FERROFLUID_WHISPER_BIN`: существующая настройка пути к Whisper CLI.

## Архитектура

Раздел добавлен в существующее окно Library. Rust-команды в `src-tauri/src/meetings.rs` управляют независимой очередью задач, прогрессом, остановкой дочерних процессов и локальными JSON-файлами. Worker встроен в приложение через `include_str!`; установка отдельного сервера не требуется.

Локальный [sherpa-onnx](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/index.html) выделяет интервалы голосов с моделями Pyannote segmentation 3.0 и WeSpeaker VoxCeleb ResNet34. Whisper CLI обрабатывает запись двухминутными фрагментами, сохраняя абсолютные таймкоды. Метки говорящих назначаются по пересечению временных интервалов; спорные и непокрытые интервалы требуют проверки.

Калибровка использует [3D-Speaker CAM++ из официальных моделей sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-recongition-models). Профиль строится из трёхсекундных окон подтверждённой речи. Проверка исключает каждое проверяемое окно из собственного профиля. Для всей записи извлекаются трёхсекундные контексты с шагом в секунду; результат требует косинусного сходства ≥0.5 и разницы с ближайшим другим профилем ≥0.12. Это эвристические пороги, не вероятность правильности. Признаки кэшируются локально для быстрых повторных запусков. Наложение речи и короткие реплики требуют ручной проверки. Подтверждённые интервалы сохраняются как ручная разметка.

Одновременно выполняется одна задача конференции. Отмена останавливает worker и его дочерние процессы. Результат анализа/транскрипции сохраняется только после успешного завершения; уже сохранённая версия остаётся доступной. После закрытия окна продолжающуюся задачу можно увидеть при повторном открытии раздела.

## Проверки

```powershell
npm ci
npm run build
cargo check --manifest-path src-tauri/Cargo.toml
py -3.11 -m unittest discover -s tests -v
npm run tauri:build -- --no-bundle
```

Тесты проверяют наложение голосов, непокрытую речь, смену говорящего внутри результата Whisper, смещения между фрагментами и сохранность слов без таймкодов. Для проверки интерфейса нужен настоящий Tauri runtime: браузерная версия показывает дизайн, обработка аудио доступна в настольном приложении.
